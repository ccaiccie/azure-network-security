# Primary sources reviewed 4 November 2026

Sources explain the design; they are not a provider, Azure or live TLS/identity test. Verify current regional limitations and schema before any authorized deployment.

- [PE subnet network policies](https://learn.microsoft.com/en-us/azure/private-link/disable-private-endpoint-network-policy): routing/NSG flags, affected subnet and eligible address-prefix override. The lab's N≥16 containing-E model is specific to the10.30/16 endpoint block, not generic shorter-prefix precedence.
- [Firewall inspection of PE traffic](https://learn.microsoft.com/en-us/azure/private-link/inspect-traffic-with-azure-firewall): application-rule proxy/SNAT for symmetric return. The custom-NVA exception below is separate.
- [Customer-NVA disableSnatOnPL option](https://learn.microsoft.com/en-us/azure/private-link/private-link-disable-snat): reference-only, not a tag applied to this managed Firewall or an implemented variant.
- [PE overview and limitations](https://learn.microsoft.com/en-us/azure/private-link/private-endpoint-overview): Approved state, read-only managed NIC, regional NSG limits and missing effective-route/security/inbound-flow-log views. Do not infer approval from allocated address.
- [Storage Private Endpoints](https://learn.microsoft.com/en-us/azure/storage/common/storage-private-endpoints): ordinary service hostname/private DNS and service-specific subresource; PE creation alone does not disable public service access.
- [Firewall DNS settings](https://learn.microsoft.com/en-us/azure/firewall/dns-settings): proxy and resolver consistency, independent of application policy Allow.
- [Pinned5.12 Storage Account documentation](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/v5.12.0/website/docs/r/storage_account.html.markdown): public_network_access enum, Shared Key/anonymous controls and exported keys. This source does not make Terraform state secret-free.
- [Pinned5.12 Storage Account implementation](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/v5.12.0/internal/services/storage/storage_account_resource.go): Resource Manager clients and schema review, not provider execution.
- [Pinned5.12 container implementation](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/v5.12.0/internal/services/storage/storage_container_resource.go): owned container create/read through Resource Manager. No Blob upload resource is supplied; actual data is seeded separately from the private VM.
- [Pinned5.12 PE documentation](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/v5.12.0/website/docs/r/private_endpoint.html.markdown): static ip_configuration, blob member/subresource, zone-group versus customDnsConfigs behavior and IP even when Rejected.
- [Pinned5.12 DNS VNet link](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/v5.12.0/website/docs/r/private_dns_zone_virtual_network_link.html.markdown): private_dns_zone_id and Default/NxDomainRedirect resolution policy. Lab uses Default.
- [Current subnet documentation](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/main/website/docs/r/subnet.html.markdown): four network-policy enum values. The pinned5.12 subnet URL returned a cache miss; schema remains unvalidated.
- [Policy rule collection group](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/firewall_policy_rule_collection_group): application rule field is destination_fqdns, not the classic resource's target_fqdns. No schema executable was loaded.
- [Container-scoped Blob roles](https://learn.microsoft.com/en-us/azure/storage/blobs/assign-azure-role-data-access): separate Reader and Contributor with exact owned container scope. Management resource permission alone does not grant Blob data access.
- [VM managed-identity token usage](https://learn.microsoft.com/en-us/entra/identity/managed-identities-azure-resources/how-to-use-vm-token): exact IMDS endpoint/header/audience and VM-wide identity security boundary. Token requests are future approved actions only; no real token was acquired here.
- [Azure IMDS](https://learn.microsoft.com/en-us/azure/virtual-machines/instance-metadata-service): host-local primary-NIC access, not a general Internet route.
- [Official cloud-init Azure datasource](https://docs.cloud-init.io/en/latest/reference/datasources/azure.html): IMDS supplies per-boot network/pre-provisioning metadata. NSG220 stays available independently of data-role grants to avoid blocking image startup.
- [Put Blob REST](https://learn.microsoft.com/en-us/rest/api/storageservices/put-blob): fixed BlockBlob PUT, date/version and conditional request behavior. RFC1123 x-ms-date is supplied; If-None-Match:* prevents intentional overwrite.201 does not replace independent content verification.
- [AZFWApplicationRule schema](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/azfwapplicationrule): source tuple/action/FQDN; TargetUrl only for HTTP or decrypted TLS, not this Standard HTTPS case.
- [StorageBlobLogs schema](https://learn.microsoft.com/en-us/azure/azure-monitor/reference/tables/storagebloblogs): ClientRequestId, authentication/status/requester/caller observations. No forced assumption that caller address equals F, S or A.
- [Firewall regional capacity](https://learn.microsoft.com/en-us/troubleshoot/azure/firewall/firewall-known-issues): East US new Standard deployment block on review date; required region is deliberate.
- [Azure pricing calculator](https://azure.microsoft.com/en-us/pricing/calculator/): estimate actual approved region/subscription costs; no live price quote here.

No source eliminates the need for actual Approved PE/DNS/route/log/identity/content evidence. SQL redirect, Files/SMB, DFS/HNS, Premium decryption, IPv6 and customer NVA no-SNAT are not implemented variants.

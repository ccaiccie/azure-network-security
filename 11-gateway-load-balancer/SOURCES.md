# Scenario11 primary sources and limits

Reviewed4 November2026. Source research and offline tests only; no Azure, real guest, packet capture, Terraform/provider or nft execution.

- [GWLB overview](https://learn.microsoft.com/en-us/azure/load-balancer/gateway-overview): supported Standard consumer chaining, VXLAN, source preservation and per-flow affinity. The frontend is not a UDR next hop; symmetry is not replicated state.
- [Create GWLB tutorial](https://learn.microsoft.com/en-us/azure/load-balancer/tutorial-create-gateway-load-balancer): Gateway frontend/pool/tunnel construction and minimum1550 NVA MTU. Actual image/kernel/underlay behavior still needs validation.
- [Microsoft complete teaching sample](https://learn.microsoft.com/en-us/samples/azure/azure-quickstart-templates/load-balancer-gateway/), [sample Bicep](https://github.com/Azure/azure-quickstart-templates/blob/master/demos/load-balancer-gateway/main.bicep), [sample NVA bridge](https://github.com/Azure/azure-quickstart-templates/blob/master/demos/load-balancer-gateway/scripts/nva.sh): External→Internal and reverse tunnel directions, nonfloating GWLB example. The original unfiltered bridge is not a firewall; this derivative supplies actual scoped bridge-family rules rather than claiming vendor NGFW capability. Original password/latest-image/download/public-NVA choices are not retained.
- [Outbound chaining tutorial](https://learn.microsoft.com/en-us/azure/load-balancer/tutorial-gateway-outbound-connectivity): outbound-initiated inspection is a distinct configuration, not included here. Established inbound replies are not new outbound initiation.
- [Health probes](https://learn.microsoft.com/en-us/azure/load-balancer/load-balancer-custom-probe-overview): separate NVA/application probes, platform source and health/flow distinctions. Local readiness, Azure probe state and actual packet path are separate evidence.
- [LB best practices](https://learn.microsoft.com/en-us/azure/load-balancer/load-balancer-best-practices): MTU/encapsulation considerations. Bounded payload success is not packet-size or PMTU proof.
- [NSG semantics](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview): source/destination enforcement and stateful existing-flow caveats.
- [Azure platform virtual IP](https://learn.microsoft.com/en-us/azure/virtual-network/what-is-ip-address-168-63-129-16): distinguish platform/agent/DNS/probe traffic; blanket egress claims are inappropriate.
- [Bastion overview](https://learn.microsoft.com/en-us/azure/bastion/bastion-overview), [required NSG rules](https://learn.microsoft.com/en-us/azure/bastion/bastion-nsg): Standard native private-target management and separate service NSG envelope.
- [Current official provider pool documentation](https://registry.terraform.io/providers/hashicorp/Azurerm/latest/docs/resources/lb_backend_address_pool): exact tunnel_interface fields and VXLAN spelling. [LB](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/lb) and [rule](https://registry.terraform.io/providers/hashicorp/azurerm/latest/docs/resources/lb_rule) define consumer chaining and rule settings. Declared AzureRM5.12.0 remains provider/schema unvalidated; direct pinned-source fetches were unavailable in this worker. No provider binary/schema execution or genuine lock file exists.
- [iproute2 VXLAN source](https://raw.githubusercontent.com/iproute2/iproute2/main/ip/iplink_vxlan.c): controller review confirmed info_data.link JSON representation for underlay linkage. Real iproute2/kernel execution remains unrun.
- [nftables bridge filtering](https://wiki.nftables.org/wiki-nftables/index.php/Bridge_filtering): bridge-family hooks are the relevant packet path; routed inet rules alone would not establish bridge filtering. The controller owns one table and leaves unrelated bridge chains accepted in its own hooks, without overriding other policies.
- [cloud-init write_files](https://cloudinit.readthedocs.io/en/latest/reference/modules.html): supports gzip/base64 content encoding; actual image/cloud-init decoding and Terraform-rendered size remain unvalidated.
- [Azure CLI queries](https://learn.microsoft.com/cli/azure/use-azure-cli-successfully-query): --query filters returned JSON client-side. It is not proof the process/diagnostics never received sensitive metadata. Treat all output/captures as private and review before sharing.

## Deliberate limits

The exact NVA inner pre/post-consumer translation boundary is not established by overview prose. The narrow C↔{P,B} candidate envelope allows investigation; first authorized captures must record actual inner and outer tuples. No invented MAC, UDP source port, translated address, TCP sequence preservation or reverse conntrack assumption is supplied.

Initial provider10.0/16 transport NSGs are a bounded proposed envelope, not a measured platform-source guarantee. If current supported deployment requires another source, stop for review; do not widen to Internet. Gateway feature eligibility, probe no-healthy behavior, region/zone capacity, compressed cloud-init rendering, Linux bridge/nft semantics, MTU and all runtime outcomes remain unvalidated.

No vendor marketplace/licensing/security features, arbitrary public endpoints, all-down or destructive failure, cross-tenant or outbound/NIC-consumer variant is implemented. These limits are not evidence of an unsupported platform capability; they delimit this teaching draft.

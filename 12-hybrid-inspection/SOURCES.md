# Sources and review boundary

Reviewed4November2026. These primary references support source design, not successful provider acceptance or Azure execution. No secret-bearing tenant API was called. Pinned AzureRM5.12.0 gateway/connection documentation fetches returned cache misses; readable current provider `main` documentation was reviewed instead. That is not a verification of the pinned binary/schema. Terraform/OpenTofu, initialized provider cache and HCL parser were unavailable. No genuine provider lock was fabricated.

- [Microsoft hybrid Firewall tutorial](https://learn.microsoft.com/en-us/azure/firewall/tutorial-hybrid-portal-policy): Azure-hosted branch simulation, paired VNet-to-VNet VPN, hub/spoke transit and separate forward/return steering. This lab chooses active-standby AZ gateways and existing immutable images, not the tutorial's active-active/package setup.
- [VPN Gateway settings](https://learn.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-about-vpn-gateway-settings): GatewaySubnet restrictions, route-based gateway role and propagation requirements.
- [Gateway SKUs](https://learn.microsoft.com/en-us/azure/vpn-gateway/about-gateway-skus) and [Standard public IP with VPN Gateway](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/configure-public-ip-vpn-gateway): current SKU/region/generation must be rechecked; no service provisioning was tested.
- [Gateway zone configuration](https://learn.microsoft.com/en-us/azure/vpn-gateway/create-routebased-vpn-gateway-cli): Standard IP zone choices determine AZ gateway placement. Full-lab zone resilience is not claimed.
- [Gateway transit](https://learn.microsoft.com/en-us/azure/vpn-gateway/vpn-gateway-peering-gateway-transit) and [Firewall hub/spoke routing](https://learn.microsoft.com/en-us/azure/firewall/firewall-multi-hub-spoke): exact spoke-prefix gateway steering, shared-gateway settings and preservation of gateway control routes.
- [Azure route selection](https://learn.microsoft.com/en-us/azure/virtual-network/virtual-networks-udr-overview): longest-prefix and equal-prefix priorities. Disabling gateway propagation also affects non-BGP gateway routes.
- [Firewall private ranges](https://learn.microsoft.com/en-us/azure/firewall/snat-private-range): expected source-preserving private network rules, distinct from application-proxy behavior.
- [Firewall rule processing and changes](https://learn.microsoft.com/en-us/azure/firewall/rule-processing): terminating collection/rule behavior and changing Allow to Deny. Actual rollout/session timing remains an observation requirement.
- [Current Firewall capacity constraints](https://learn.microsoft.com/en-us/troubleshoot/azure/firewall/firewall-known-issues): East US Standard deployment restriction still listed on review date. No region default is supplied.
- [AzureRM gateway current source documentation](https://github.com/hashicorp/terraform-provider-azurerm/blob/main/website/docs/r/virtual_network_gateway.html.markdown) and [connection documentation](https://github.com/hashicorp/terraform-provider-azurerm/blob/main/website/docs/r/virtual_network_gateway_connection.html.markdown): current `bgp_enabled`, route-based gateway and reciprocal peer IDs/shared_key. Older Basic/dynamic public-IP examples were not copied.
- [Connection GET schema](https://learn.microsoft.com/en-us/rest/api/network-gateway/virtual-network-gateway-connections/get?view=rest-network-gateway-2025-09-01): generic connection schema lists password-type sharedKey. No omission guarantee or actual secret receipt is asserted. Default collector skips these reads; optional informed response handling does not turn client-side projection into a security boundary.
- [Azure CLI query behavior](https://learn.microsoft.com/en-us/cli/azure/use-azure-cli-successfully-query): `--query` filters the returned object locally. Full API receipt, errors, free text and caches need private handling.
- [Terraform sensitive data](https://developer.hashicorp.com/terraform/language/manage-sensitive-data): sensitive marking suppresses display but does not eliminate persisted state/plan exposure. This lab does not generate or handle a real key.
- [AzureRM workspace source documentation](https://github.com/hashicorp/terraform-provider-azurerm/blob/main/website/docs/r/log_analytics_workspace.html.markdown): shared-key exported attributes mean workspace state also needs secret handling, despite disabled local authentication.
- [VPN monitoring](https://learn.microsoft.com/en-us/azure/vpn-gateway/monitor-vpn-gateway) and [monitoring reference](https://learn.microsoft.com/en-us/azure/vpn-gateway/monitor-vpn-gateway-reference): selected diagnostic categories, metric dimensions and AzureDiagnostics. Definition collection is not a measurement; no BGP metrics should be mistaken for non-BGP route proof.
- [Bastion peered-VNet access and limitations](https://learn.microsoft.com/en-us/azure/bastion/bastion-faq) and [Bastion NSGs](https://learn.microsoft.com/en-us/azure/bastion/bastion-nsg): distinct private management and required service envelope.
- [ExpressRoute FastPath](https://learn.microsoft.com/en-us/azure/expressroute/about-fastpath) and [ER/VPN coexistence](https://learn.microsoft.com/en-us/azure/expressroute/expressroute-howto-coexist-resource-manager): separate real-service prerequisites and feature-dependent paths, not implemented or tested by this VPN simulation.

Local checks explicitly separate source text, Python/INI/shell syntax, guarded loopback fixture behavior, fake CLI identity checks, a route-selection teaching model and supplied unexecuted plan-only provider mocks. None is actual HCL evaluation, secret injection, systemd startup, IPsec negotiation, route propagation, firewall enforcement or cloud teardown.

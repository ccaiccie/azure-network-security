# Scenario 09 primary sources and validation limits

Reviewed 2026-11-04. Source review and local mocks are not provider/schema/API/vendor/guest proof. No login, cloud operation, vendor installation, license purchase or Terraform execution occurred.

- [Microsoft integrated NVAs in a virtual hub](https://learn.microsoft.com/en-us/azure/virtual-wan/about-nva-hub): supported integrated product categories, external partner/managed-application ownership and configuration. A named vendor family alone does not prove exact offer/version/region compatibility.
- [Routing intent](https://learn.microsoft.com/en-us/azure/virtual-wan/how-to-routing-policies): Internet-only Default association/Default propagation, next-hop ownership, platform steering and removal side effects. Private-only propagation differs.
- [Internet routing](https://learn.microsoft.com/en-us/azure/virtual-wan/about-internet-routing): direct-egress model and distinct vendor routing/SNAT requirements.
- [Effective route views](https://learn.microsoft.com/en-us/azure/virtual-wan/effective-routes-virtual-hub): actual entity selection, route fields and connection default-learning flag. Do not infer source NIC selection from hub state alone.
- [Azure route selection](https://learn.microsoft.com/en-us/azure/virtual-network/virtual-networks-udr-overview): longest prefix and route-source precedence. A competing user default could defeat this intended path.
- [Default outbound access](https://learn.microsoft.com/en-us/azure/virtual-network/ip-services/default-outbound-access): explicit disabling is not a routing instruction or a substitute for NSGs.
- [NSG semantics](https://learn.microsoft.com/en-us/azure/virtual-network/network-security-groups-overview): tuple evaluation versus platform public-IP translation and existing state caveats.
- [Bastion forced-routing troubleshooting](https://learn.microsoft.com/en-us/troubleshoot/azure/bastion/troubleshoot-connection-fails-routing-forced-tunneling): separate non-forced management VNet peered to target as the selected correction.
- [Bastion FAQ](https://learn.microsoft.com/en-us/azure/bastion/bastion-faq): default propagation/forced-routing restrictions and no Bastion-subnet UDR workaround.
- [Bastion overview](https://learn.microsoft.com/en-us/azure/bastion/bastion-overview): private target access across VNet peering and Standard native-client capability.
- [Bastion NSGs](https://learn.microsoft.com/en-us/azure/bastion/bastion-nsg) and [CLI](https://learn.microsoft.com/en-us/cli/azure/network/bastion?view=azure-cli-latest).
- [NVA GET schema](https://learn.microsoft.com/en-us/rest/api/virtualnetwork/network-virtual-appliances/get?view=rest-virtualnetwork-2025-05-01): linked virtualHub, nvaSku and secret-prone bootstrap/cloud-init fields. The collector filters normal stdout to selected fields; Azure CLI may first receive the full secret-bearing response; this is not an automated proof of final public translation or policy.
- [Azure CLI query behavior](https://learn.microsoft.com/cli/azure/use-azure-cli-successfully-query): `--query` is client-side filtering of returned JSON before display formatting. It is not server-side minimization or a diagnostic-log redaction boundary.
- [vhub CLI](https://learn.microsoft.com/en-us/cli/azure/network/vhub?view=azure-cli-latest): requires approved virtual-wan extension; RouteTable effective routes are used, not a fabricated vendor-token command.
- [Provider virtual_hub_routing_intent](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/main/website/docs/r/virtual_hub_routing_intent.html.markdown) and [virtual_hub_connection](https://raw.githubusercontent.com/hashicorp/terraform-provider-azurerm/main/website/docs/r/virtual_hub_connection.html.markdown): current official source docs reviewed; exact AzureRM5.12.0 schema and computed-field reconciliation remain unexecuted.

## Vendor boundary

No schema-specific vendor installer, manager API adapter, license workflow, policy installer, log exporter, session-clear or failure controller was implemented or tested. The typed profile is intended only for NONSECRET product identity and policy identifiers. Free-text values are operator-reviewed, not automatically redacted, and the collector retains declared Terraform outputs including that profile. Keep outputs/logs/evidence private and review/redact an approved copy before sharing. Projected Azure command output compares limited identity fields. Those comparisons cannot establish licensing, compatibility, manager health, effective policy, full E pool, NAT/session mapping or reverse routes.

Select and review current official vendor documentation for the actual Marketplace publisher/offer/plan, versions, region and integration before treating this as an executable end-to-end experiment. Never use a generic Azure Firewall KQL table for partner appliance traffic. Missing supported vendor steps are an explicit prerequisite/blocker, not permission to substitute a different appliance.
